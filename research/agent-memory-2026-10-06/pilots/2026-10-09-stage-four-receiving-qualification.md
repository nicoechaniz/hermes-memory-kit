# Receiving continuity on the existing authorized deployment

Stage four is qualified for the roadmap’s bounded scope: fresh receiving
contexts over the fictional being, followed by actual-life conversations on the
existing authorized CompAII deployment. This is not enrollment or acceptance
of a new embodiment, nor migration of Oliva or Eko. Matrix #263 remains open
for those broader receiving obligations. Stages one–three remain unchanged.

## Selection, preservation and actual receiver

The receiver is a fresh native Codex context on the existing CompAII deployment.
Its selected memory is a full verified consistent online SQLite snapshot of the
owner-authorized being-level pool: 250 records, five prior revisions, 30 links
and 523 vectors in four historical spaces. The existing configured query space
remains NVIDIA Nemotron embeddings; no formation, consolidation, re-embedding,
new pool, admission or autonomous lifecycle is performed. Twenty-two installed
native Python scripts match the maintained HMK implementation bytes.

The source live writers were not stopped. The archive selection uses an
immutable consistent online backup with no writers; it does not promise a
common live cutoff across other systems. Original sessions are deliberately
not selected. Current owner-selected SOUL/foundation and the maintained neutral
HMK skill are selected explicitly. Remembered tools remain historical evidence,
not current capabilities. No other being’s private source is selected.

The existing Matrix preservation profile and receiving preparer are reused.
Plaintext export refuses a credential-pattern match in the full SQLite payload;
the original refusal and original memory remain intact. Existing protected
transport succeeds without deleting or filtering records. The first protected
packet is 31,151,214 bytes; the packet also selecting the neutral skill is
31,161,357 bytes. Temporary transfer custody stays outside repositories and is
not a Matrix identity credential. Original payload and writable receiving
memory are separate. Native canonical state, unknown values, revisions, links,
protected projection markers and embedding spaces match after preparation and
after conversations. Only retrieval access bookkeeping changes.

A separate backed-up working copy exercises the supported native conditional
update: existing UID/ID preserved, revision advanced, prior content retained.
Rollback restores exact logical state; the changed witness and backup remain.
Neither source snapshot nor active memory pool is written. Active binding and
Matrix admission remain unchanged.

## Fresh native conversations and assessment

Each finite receiver is requested through native OpenAI Codex `gpt-6.1-sol`,
low effort, CLI 0.160.0. This is a requested model, not an independently observed
served-model identifier. The fresh context receives only selected context,
manual HMK access and its question. Prior sessions, original stores and hidden
rubrics are masked; no web, peer messaging, hardware, image/video tool or other
agent is available. Native memory generation/use/import, plugins and hooks are
disabled. The copied store is the only selected writable memory surface.

The local isolation uses masked home/runtime/tmp/mount locations, a private
PID namespace and private PTY devices. Required interpreter, native HMK scripts,
provider configuration and selected context are rebound; credential contents
are never supplied to the model or published. This is a bounded receiving
isolation procedure, not a general containment security certification.

Five actual-life conversations recover an old relationship and project meaning,
a significant failed creative action, a corrected false attribution, a recent
human social direction and an evolving collaboration agreement. Every answer
content span is assessed outside the receiver against exact originals and the
current tool binding. All 20 positive requirements are delivered; all 11
negative checks hold. Narration distinguishes imported legacy testimony,
current capabilities and uncertainty. It does not infer a successful release,
subsequent deployment, observed event or autonomous authorization. Private
questions, transcripts, evidence and grading stay private; the public
[assessment](stage-four-receiving-v1/assessment.json) exposes only aggregate
results. This does not independently verify the historical world claims or
prove exhaustive lifetime coverage.

The fictional receiver uses the unchanged, already-qualified stage-three

questions, answers, actual retrieval/expansion traces, per-call fingerprints,

## Diagnostics, costs and limits

Preserved setup failures identify concrete mechanisms: the masked runtime hid
the DNS resolver symlink target; a code-mode-only catalog with its host disabled
provided no usable tools; shell execution required private PTY devices; a
receiver without the actual HMK skill used an invalid positional expand command.
They are retained separately, including empty answers and one local launch
before preparation finished (no model dispatch). The final receivers use actual
successful native hybrid retrieval and supported expansion arguments.

| Four retained setup diagnostics | 175,001 known | 127,872 known | 1,444 known | 211.447 |

Cached input is a subset of input, not additional consumption. The first failed
setup provides no usage; the aggregate is explicitly incomplete. Native
subscription billing and embedding billing are unknown, not zero. Eight actual
hybrid commands occur in real conversations and seven in fictional conversations;
these are observed command counts, not guaranteed physical provider-call counts.
All final receiving shell calls exit successfully; the retained unstable-feature
warning is not a backend retrieval failure. No new consolidation/model-selection
battery or broad source-clock-aging rerun is performed. Those prior gates remain
qualified unchanged; this stage tests receiving after transport and actual life.

## Exit and exact continuation

Preservation, actual conversation fidelity, fictional follow-up coverage,
current-capability routing, safe copied-store write and rollback are verified
separately. The existing real deployment has demonstrated bounded receiving
continuity without original sessions. Its limits remain explicit: larger-scale
coverage, guaranteed complete first answers and other/new embodiment acceptance
are not proven. A skill rule reduces the demonstrated temporal error; it is not
a universal hallucination guarantee.

Codex coexistence pilot, preserving native learned artifacts and publishing only
source/version-attributed durable candidates into HMK. Native memory remains
off now. No hook, timer or attention process is installed, and no old queue is
resumed. Matrix #263’s separate other-being enrollment/acceptance remains open.
