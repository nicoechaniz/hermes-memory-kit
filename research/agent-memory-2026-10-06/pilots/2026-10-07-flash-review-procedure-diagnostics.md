## Corrected proof procedure

The [finite batch receiver](receiving_batch.py) uses per-question checkpoints,
at most three workers, an explicit invocation call ceiling, and the existing
bounded structural/semantic budgets. Every future is inspected. Unresolved
observed dispatches cannot be implicitly repeated. Raw response reuse requires
identical actual provider parameters, request/model identity, completed receipt
and matching response content; local verdicts and attempt budgets never migrate.
Imported work retains its actual receipt and incurs no new inference call.

`passages/v1` presents numbered original source headers and decoded quotation
blocks. The verifier selects `{id, passage}` rather than retyping proof prose.
The adapter materializes the original text and checks cited-source membership;
every assertion/span, verdict, proof and missing requirement still undergoes
validation and outside semantic grading. Original model responses remain intact
beside their canonical quoted reviews. Passage selection cannot establish
entailment or turn generated understanding into independent corroboration.

The legacy literal protocol separately records a narrow terminal-period to
original-semicolon syntax repair. It changes no words, source IDs, spans or
verdicts, and cannot repair question marks or conditional commas. Invalid or
uncited proof remains rejected. Changed validation is fingerprinted as
`narrative-shape/v3`; old accepted/pending work requires its original code or a
new explicitly versioned comparison. The original nine-candidate Flash run and
all later diagnostic checkpoints remain available with frozen implementations.

The current complete v6 candidate uses low-effort Flash for both roles and the
passage proof protocol. Initial generations are reused from v5 only where actual
prompts, schema and provider parameters match; reviews use the new protocol.
All 44 questions still require outside claim/requirement grading. Formation,
embeddings and retrieval have not changed in these receiving-only trials.
